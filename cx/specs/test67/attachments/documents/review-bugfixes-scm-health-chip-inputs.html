Bugfixes-Scm — a verb that needs inputs is its own model, not a payload contract

Review of Bugfixes-Scm (2026-09-08), point 2 of 4: the health chip asking for a repository. Written for Ali El Hajjar. Companion of review-bugfixes-scm-token-username.html.

1. The original problem

The SCM sheet's probe cell has an optional input cell, probeRepository, defaulting to empty. A bare scm.git row that no project uses gives git nothing to dial: the wire protocol is repository-scoped. The probe therefore could not run and failed with "open the SCM screen and enter one". The goal was to let the user name a repository from the health chip and test again. Legitimate goal.

2. What the branch built, and why it is the wrong shape

The branch makes the server describe the missing input in the result, and makes the generic chip understand that description. Three layers change for one input on one verb:

LayerBranch changeProblem
TestResult (build-client)gains a nullable requestedInput (FormField)A domain result type now carries a UI protocol. Every other result type that ever wants to ask must copy the field.
IInputRequestingOutcome (platform-forms-api)new platform contract, one FormFieldExactly one input. A probe that needs a repository and a branch cannot express it. New public API surface for one caller.
StateVerbModel (entity-model)remembers one cell + one answer, builds a FormRequest with a null agent name, opens a dialog, clears the seed on failure, gates on the checking flag so live deliveries do not pop dialogs, plus a new dependency on platform-forms-api and ~15 mock-driven testsA generic pip-and-Test chip now contains a state machine about repositories. None of it is about health pips.
The root mistake: treating the chip as the one and only model every verb must fit into, so the verb's specifics had to be smuggled through the payload. The chip is a model like any other. A verb with inputs is a different model.

3. The shape to build instead

The registration in BuildApplicationModule already chooses the model per entity and role. Let it choose a verb-specific model with its own view when a verb needs inputs. The generic StateVerbModel stays the plain pip + Test and gets exactly one hook: a template method where a subclass seeds its inputs into the same committed batch. The server probe goes back to being a plain probe.

  • The client already knows its domain. build-model registers the SCM verb and knows the probe wants a repository. It does not need the server to say so, and it can show a real picker over the project's repositories instead of a generic text box.
  • N inputs is free. A model has as many properties as it needs, each a real widget in its own view JS. No form request, no field list, no remembered seeds.
  • It follows the platform's own rule. One model, one view; promote to a shared base only when a pattern repeats (ui-screen-design-guidelines.md). No new contract in platform-forms-api, no kb section, no field on TestResult.

Pseudo-code

domain/entity-model/.../inspector/StateVerbModel.java (generic; keep the branch's single watch channel with the failure arm)

public class StateVerbModel extends AbstractModel {

    // subclass constructor: same arguments as create(...), plus the subclass's own view class
    protected StateVerbModel(Class<? extends IView> view, DisplayContext ctx, String sheetName, String cellName,
                             String label, Function<Object, String> outcomeInterpreter) { ... }

    @Action(name = "onTest", description = "Runs the health check for this row")
    public void onTest() {
        applyStatus(VerbStatus.CHECKING, "");
        IObserverTx tx = clientOrOpen().begin();
        tx.override(sheetName, IEntityInstanceSheet.SUBJECT, rowId, rowId);
        seedInputs(tx);                                        // NEW — the only generic change
        IDrivenCell<Object> driven = tx.evaluateCell(sheetName, cellName, rowId, Object.class);
        tx.commit();
        bindLive(driven);                                       // 4-arg watch: value → applyOutcome, thrown → applyFailure (branch, keep)
    }

    /** Seeds the cells this verb's inputs drive, in the same batch as the evaluate. Default: nothing. */
    protected void seedInputs(IObserverTx tx) { }

    protected Object getRowId()      { return rowId; }
    protected String getSheetName()  { return sheetName; }
}

domain/build/build-model/.../scm/ScmProbeVerbModel.java (the SCM verb's own model)

/**
 * The SCM connection's health verb: the stock pip + Test, plus the repository to probe against when no
 * project uses the row yet. A forge-backed row needs none (the probe goes through the forge); a bare
 * scm.git row shows the field. Its own model + view, as every screen widget is.
 */
public class ScmProbeVerbModel extends StateVerbModel {

    private final IObjectProperty<String> repository;          // what the user names
    private final IObjectProperty<List<String>> candidates;    // repositories of the projects on this row, if any
    private final IBooleanProperty needsRepository;             // bare scm.git row with no project → show the field

    public ScmProbeVerbModel(DisplayContext ctx) {
        super(ScmProbeVerbView.class, ctx, IScmConnectionSheet.NAME, IScmConnectionSheet.PROBE,
              "Connection health", ScmProbeVerbModel::failureOf);
        // needsRepository / candidates: read off the row (location is scm.git, not a forgeRef) and the
        // project sheet, through the same observer client the chip already opens
    }

    @Override protected void seedInputs(IObserverTx tx) {
        String repo = repository.get();
        if (repo != null && !repo.isBlank()) {
            tx.override(getSheetName(), IScmConnectionSheet.PROBE_REPOSITORY, getRowId(), repo.trim());
        }
    }

    private static String failureOf(Object payload) {          // failure-as-value, as today
        return payload instanceof TestResult r && !r.success() ? r.message() : null;
    }
}
// ScmProbeVerbView.java + ScmProbeVerbView.js: pip, Test button, and — when needsRepository — a repository
// field (autocomplete over candidates when there are any, free text otherwise) with the helper text
// "No project uses this connection yet; name a repository to test against." Two inputs tomorrow = two fields.

domain/build/build-model/.../BuildApplicationModule.java (the registration picks the model, as it already does)

registry.register(ScmEntity.ENTITY_CLASS_KEY, DisplayRole.INSPECTOR, ScmProbeVerbModel::new);

// forge: the plain chip, registered ONCE (the branch registers it twice — delete the duplicate block)
registry.register(ForgeEntity.ENTITY_CLASS_KEY, DisplayRole.INSPECTOR,
        ctx -> StateVerbModel.create(ctx, IForgeConnectionSheet.NAME, IForgeConnectionSheet.PROBE,
                "Connection health", p -> p instanceof TestResult r && !r.success() ? r.message() : null));

What to delete from the branch

  • TestResult.requestedInput, TestResult.missing(...), the @JsonInclude, the 3-arg creator; TestResultWireRoundTripTest goes back to two fields.
  • cyai.forms.IInputRequestingOutcome and its CLAUDE.md entries.
  • entity-model's new dependency on platform-forms-api.
  • StateVerbModel: the input fields, requestInput / showAsk / withDefault, the dialogs injection and the checking gate in applyOutcome; the ~15 input tests. Keep applyFailure as the shared failure path (without the seed clearing).
  • kb observer-sheets.md section 5.4c and the matching BuildApplicationModule comment.

What to keep from the branch

  • The single outcome channel: the 4-arg watch with the onFailed arm, the removed future consumer, the "a live re-delivery never opens a dialog" reasoning (now moot, but the channel is right).
  • The probeThroughForge(scm, forgeId, ...) reordering and its javadoc.
  • The FormRequestDialogs rename, if you like it. It is harmless either way.

Tests (same unit of work)

  • ScmProbeVerbModelTest: a named repository is seeded on probeRepository at the row id in the same batch; a blank one seeds nothing; the field is shown for a bare row and hidden for a forge-backed one.
  • StateVerbModelTest: the existing pip cases + one case that the default seedInputs seeds nothing.
  • ScmConnectionSheetTest: bare row, no project, no repository → plain failure naming the repository.

4. When would a server-described ask be right?

Only when the server decides at runtime that it needs something the client could not know when the screen was built. That plane already exists: agent forms through IFormSink / FormRequestDialogs. If a sheet ever needs it, it asks through that, not through a second protocol on the result payload. The SCM probe is not that case: what it needs is static, known to the module that registers its chip, and better rendered by a widget that knows the domain.

Rule of thumb for next time. If a generic model starts learning things about one entity, the fix is a model for that entity, not a contract that lets the server teach the generic model. The registration already exists to choose it.
